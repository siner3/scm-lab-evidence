# Reflection

## Q1. How do Issues and pull requests together support change control?

Issues describe the problems and the changes needed. Pull requests show the code changes to solve those problems. They allow people to review changes before merging into main.

## Q2. Why did the conflict in Part 4 happen, and how could a team reduce such conflicts?

The conflict happened because two branches changed the same line differently. Branch A changed it to staging, while Branch B changed it to production. A team can reduce conflicts by communicating and merging changes regularly.

## Q3. What would be lost if people merged straight into main without a pull request?

There would be no proper code review before merging. Mistakes might not be noticed. The team would also lose useful feedback and change records.
